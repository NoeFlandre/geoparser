# Glossary

This page defines the project terms. Each term has one meaning in all the documentation.

| Term | Definition |
| --- | --- |
| Toponym | A place name in a text. Example: "Zurich". |
| Geoparsing | The process that finds toponyms in a text and links each toponym to a place on Earth. |
| Recognizer | A module that finds toponyms in a text. |
| Resolver | A module that links a toponym to one record in a gazetteer. |
| Module | A recognizer or a resolver. |
| Gazetteer | A database of places. Each place has a name and a location. |
| Project | A saved workspace. It holds the texts, the toponyms, and the results of the runs. |
| Reference | The toponym that a recognizer finds in a text. |
| Candidate | A gazetteer record that a resolver can select for a toponym. |
| Annotation | A toponym or a link that a person or a module adds to a text. |
| Checkpoint | A file with the trained weights of a machine learning model. |
| Benchmark | A fixed test that measures the quality of a module. |
| Mutation testing | A test method. The tool changes the code and checks that the tests fail. |
| ADR | Architecture Decision Record. A short document that states one design decision. |
| STE | ASD-STE100 Simplified Technical English. A controlled language for technical documents. |
